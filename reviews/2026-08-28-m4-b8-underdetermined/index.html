3 · The msg 946 rule

The decision. With constant p, q and r, the note is silent exactly when q > 0, p ≤ r, and q divides r − p. Every other triple draws 946: a zero q, a negative q, p above r, and a q that does not divide r − p. D5.1's implementation note and M4-18 both say "wrong-signed". The chunk reads that word against the decoded magnitude exit of D5.1 as amended, loop while r − i ≥ 0. A negative q never steps toward r. With p ≤ r the loop never terminates; with p > r the body runs once and exits. So a descending loop like 12(-1)1 notes. A constant is a numeric literal or one under a minus. A field-name bound is not constant and draws nothing. One message text covers the four conditions. _noteConstantParameters and _constantBound carry it.

The evidence. The one condition:

The test drives DO RTN FOR IDX = p(q)r over a twelve-element table under --pedantic:

ParametersResult
1(1)12, 2(5)12, 12(1)12, +1(+1)12silent
1(0)12, 12(1)1, 1(5)12, 1(2)12946 at severity 1, card 7, clause 1, operand IDX; default mode silent
1(-1)12946, then the generator refuses the signed bound; default mode keeps the refusal alone
NUM(1)12silent: a field-name bound is not constant

The negative arm has one pinned case, 1(-1)12. The generator refuses any signed bound as a shape with no sample instance (M4-13's chunk B5 refusals). So a descending loop notes and then refuses too. The note is the only record the listing keeps of such a loop; item 6 says why it survives the refusal.

What would mislead. D5.1's implementation note was written under the equality exit, and it says "q has the wrong sign". A reader takes "wrong" as "against the direction from p to r", which is F's macro expansion. The amendment of 2026-08-05 changed the exit: the loop now runs while r − i ≥ 0. Under that exit a descending loop has no direction to be wrong against. It runs the body once when p > r, and forever when p ≤ r. 12(-1)1 is the surprising case: the programmer expects twelve passes, and the decoded exit gives one.

The rejected options.

A — F's direction reading
q is wrong-signed only when its sign differs from that of r − p. Cost: 12(-1)1 is then silent, although the decoded exit runs its body once and leaves the loop. The note passes over the case the decode made surprising, and a later reader takes the silence as a working loop. The reading also fits the exit the record no longer holds.

B — three ids, one per condition
Cost: M4-18 reserves one id, 946, for the D5.1 note. Three ids need an amendment to M4-18 and two more checklist rows for one family of conditions. The listing gains nothing a reader can act on: the fix is the same, rewrite the parameters.

C — silent only when q > 0, p ≤ r and q divides r − p (taken)
The condition is the decoded exit's own: the index steps from p to r exactly, or it does not. To overturn: one commit at the one condition in _noteConstantParameters and one test row. What overturns it: a period source that shows the 1962 compiler's own check, or a ruling that the note follows F's expansion, not the decoded exit.

4 · The msg 947 containment model

The decision. D5.7 asks for "static cycle detection over the DO call graph". A graph needs a rule for which procedure a DO belongs to, and the record gives none. The chunk takes the generator's own walk state. A DO, or an AT END DO, belongs to the DO'd paragraph and the section open around it. Those are _openParagraph and _openSection, the same state the return cells use. A call notes when its target can reach, through the graph, one of the procedures open around it, itself included. One note per offending call site, so a two-procedure cycle notes at both DOs. A DO outside every DO'd procedure, on the main line, never notes. _doEdge records each site during the walk, and _noteReentrantCalls reads the graph after it.

The evidence. The edge and the check:

ProgramResult under --pedantic
START. DO P. then P. DO Q. and Q. DO P.947 twice, severity 2: at card 6 naming Q, at card 7 naming P; the main line's DO P is silent
a section S whose inner paragraph P writes DO Sone note, at card 7
P. GET IREC, AT END DO P.one note, at card 9
P. DO Q. and Q. SET N = 1.silent: nesting without a cycle

Default mode draws nothing in each case, and the code dump is the same in both modes (D11.4).

What would mislead. A reader could expect the graph over the parser's paragraphs. This compiler has no parsed paragraph: a DO'd label's span runs to the next label or its END, which is the walk's own state (M4-13). A GO TO-only target takes no cell and opens no span, so it is no node. "Cycle" also misleads: a two-procedure cycle is one cycle and two lost returns, one at each SXA.

The rejected options.

A — one note per cycle
Cost: the programmer reads one site and misses the other, and both sites overwrite a pending return. The listing then reports one of two faults.

B — a flow-sensitive model through GO TO chains
Cost: D5.7 asks for static detection over the DO graph and no more. A GO TO reading invents a control-flow analysis no record asks for, and the section 12 rule allows no invention beyond the record. A GO TO out of a DO'd procedure is D5.4's own matter.

C — the walk's own containment, one note per site (taken)
The state that places the return cells is the state that knows which returns a call can lose. To overturn: one commit at _doEdge and _noteReentrantCalls; four tests. What overturns it: a ruling that D5.7's graph should follow GO TO, or a period source for the 1962 compiler's own check.

5 · The stop shape

The decision. D10.2 has each phase catch StopCompilation itself and return a partial result with a stopped flag; M4-2 defers the generator's shape to this chunk. A severity 5 inside the generator returns CodegenResult.stopped(): no assembly units, a null image, stopped true. The driver keeps the diagnostics recorded up to the stop from the sink and merges them into the job's card-ordered block (M2-2). --emit-code closes the empty * TEXT section with the stopped line, and --emit-object prints the same line in place of the object pages. [J 90.04.02]: a severity 5 "causes the compiler to stop compiling. It then proceeds to the next job." The 1962 compiler produced no object program past a severity 5, so there are no object pages to print.

The evidence. The catch and the return:

The test compiles a two-job deck. The first job crosses 3500 names in the generator: 942, stopped true, no units, no image, and the deck's severity is 5. The second job compiles clean. The code dump prints the first job's header, * TEXT, then * STOPPED IN THIS STAGE, and the second job whole.

What would mislead. D10.2 says a phase "returns its partial result", and for the front end that result is the source echo up to the stop. A reader could expect the generator's partial text in the same way. The words placed before the stop are not a program. The pool follows the whole text, so no CP)+NN has an address; no EQU has a value; no block has an origin. The generator's partial result is its diagnostics, and the sink already holds them.

The rejected option.

A — keep the words placed before the stop as a partial text
Cost: the units carry unresolved addresses, so a layout the stop never reached must be invented to print them. A later reader of the dump takes the fragment for object text. The 1962 listing never printed one.

B — no text, no image, the stopped line (taken)
The shape every earlier phase already has, and the one [J 90.04.02] describes. To overturn: one commit at CodegenResult.stopped and the two emit sites. What overturns it: a period listing that prints object text after a severity 5.

6 · Diagnostics ride on the measuring pass

The decision. The generator walks the text twice (M4-4 as amended): pass one measures, pass two places. CodegenChecks — the sink, the tally and the pedantic switch — rides on pass one only, and pass two carries none. So nothing reports twice. The decisive consequence: a refusal, UnrecoveredShape, throws from the sizers on the measuring pass, and a note emitted ahead of it survives. DO RTN FOR IDX = 1(-1)12 under --pedantic records 946 at the DO and then refuses the signed bound. The note prints in the listing, and default mode keeps the refusal alone.

The evidence. The two calls:

The test 'a negative step notes ahead of the refusal it then draws' pins it. The job's diagnostics are ['946,00']. The refusal names a DO FOR bound of UnaryExpr, and codegen is null. Default mode records nothing.

What would mislead. Pass two knows every address, and a reader could think a diagnostic needs one. None does. Every note anchors on a card and an M2-6 clause number, and the capacity messages anchor on the sentence the walk is in.

The rejected options.

A — the placing pass
Cost: a program that refuses on pass one never reaches pass two, so the negative-step arm of 946 is unreachable. CLAUDE.md section 11 then bans that arm as code no run reaches, and the listing keeps no record of a loop that never terminates.

B — both passes, with a second mechanism to drop the repeat
Cost: a de-duplication rule for diagnostics that gains nothing, since pass two reports nothing pass one did not.

C — the measuring pass only (taken)
The first walk sees every site, and it is the walk a refusal ends. To overturn: one commit at runCodegen's two generateProcedure calls. What overturns it: a diagnostic that needs an object address, which no record asks for.

7 · The allocator crossing leaves the LOC and GN columns blank

The decision. When the 3501st name is the allocator's, GN)000 or a source-order generated label, the semantic layer stops at that entry. allocateDictionary runs inside the semantic layer's StopCompilation net, so allocation stays null. The listing prints blank LOC and GN columns, as it does for every semantic stop (M3-8; D10.2), and the code generator does not run.

The evidence. The three allocator entries and the net:

The test declares 3500 one-character fields. The program entry's own name, GN)000, is the 3501st, entered at the first procedure sentence: 942 at card 3503, semantics.stopped true, allocation null, codegen null.

What would mislead. The crossing happens inside the allocator, the phase that prints the LOC column, so a reader expects the column filled up to the crossing. M3-8's print is one model: the annotations return whole at the end of the allocation, and a thrown stop discards the return value. That is D10.2's own rationale for the phase-internal catch. A stop in the resolver leaves the columns blank the same way.

The rejected option.

A — complete the allocation after the stop and print the columns
Cost: D10.2 stops each phase at the point of detection, with later work undone. A filled column after a severity 5 would be the first phase to print work past its stop. The listing would then differ between a stop in the resolver and a stop in the allocator, for no reason either manual gives.

B — the columns stay blank (taken)
One rule for every semantic stop. To overturn: one commit in semantics.dart, a catch around the allocator alone that keeps its annotations. What overturns it: a period listing that prints dictionary addresses past a severity 5.
