Review record · 2026-08-16 · chunk B4 · commit b38bd40

Two rules one program cannot settle

Chunk B4 is the comparison generator: it fills the mnemonic, operand and OCTAL columns of every IF, every conditional GO TO and the truth function's compare in the 1962 payroll sample, and every line it fills matches the listing byte for byte. Six rules carry it. Four rest on several sites or on the machine itself. Two do not — one site attests each, and a rival formulation fits the same ink. Both are taken under the section 12 standing rule, and silence lets them stand.

What was decided, in four lines

  1. The extraction spill writes result-storage cell 0 of the section the walk is in, always — not the first cell the statement's parks leave free. One site spills, and it parks nothing, so the two rules print the same ink there.
  2. The subscripted comparand's LAC PI)n,r takes the lowest free register under M4-9's statement allocator — not a fixed XR2. One site, and its XR1 is already occupied, so the two rules print the same ink there too.
  3. Each rejected formulation reproduces the 1962 listing exactly as well. They part on programs the one surviving sample does not contain, so no further scan work would choose between them.
  4. Each is one commit to overturn, in lib/src/codegen/procedure.dart, and nothing outside that file depends on either.
Decided

1 · Which result-storage cell the spill writes

The decision. When both operands of an alphameric comparison need extraction, the first extraction spills so the compare can read it back. The spill writes cell 0 of the walk's section: SLW RS)0, then LAS RS)0. _alphamericComparison in procedure.dart passes cell 0 at both references, and M4-11 as amended records it.

Why the number matters. M4-4 as amended reserves the cells as constants of the sample — 3, 2, 3 and an undivided 7 — on Jack's ruling of 2026-08-15. A rule that skips parked cells could push a compare past its section's reservation and refuse a program the cell-0 rule compiles.

The evidence. One site spills in the whole program: statement 200, the two-character department compare. Its statement parks nothing, so cell 0 and the first free cell coincide there:

What would mislead. B3's park rule numbers cells by counting a statement's operands, so a reader could expect the spill to enter that count. It does not need to: the spill is dead before any park could write — the LAS five words later is its only reader, and no park can be emitted inside a compare.

The rejected option.

A — the first cell the statement's parks leave free
Extend B3's counting rule to cover spills, so a spilling compare in a statement with two parks writes RS)2. Cost: it agrees with the one attested site. It parts from the taken rule on an IF whose arms also park, where it prints a higher cell and can push the section past its reservation. It also makes the spill cell depend on clauses that follow the compare, which no reader could see from the compare itself.

B — cell 0, always (taken)
The spill's lifetime is closed inside the compare, so it needs no slot in the park count and cannot collide with one. Cell 0 is the least machinery: no counting rule reaches across clause boundaries into the arms. To overturn: one commit at _alphamericComparison's two _resultCell calls; the oracle re-checks the site. What overturns it: a compiled listing whose spilling compare sits in a statement that also parks.

Decided

2 · Which register the subscripted comparand's prologue takes

The decision. A subscripted comparand's prologue — LAC PI)n,r / TXL SYS)294,r,0, then the compare against 0,r — takes the lowest free index register under M4-9's statement allocator, the same rule the base-locator guards use. The register then leaves the locator cache: it holds an element address now, not a base. _indicatorPrologue in procedure.dart carries it, keyed so an indicator never collides with a locator, and M4-11 as amended records it.

The evidence. One site compares a subscripted operand in the whole program: statement 225's table search. XR1 already holds BL)2 for the located 1)RATE, so the lowest free register is XR2 — which is also what a fixed-XR2 rule would print:

What would mislead. The site prints XR2, which reads as a convention — "indicators ride in XR2" — until the occupancy is checked. XR1 is taken by the locator load two words earlier, so the lowest-free rule prints XR2 here for its own reason, and the site cannot separate the two rules.

The rejected option.

A — a fixed XR2 for every indicator prologue
Cost: it agrees with the one attested site. It parts from the taken rule on a compare whose subscripted operand arrives with both registers free, where it prints XR2 and the taken rule prints XR1. It also needs its own collision rule for a statement whose locator guard wants XR2, which M4-9's allocator already settles for free.

B — M4-9's lowest-free rule (taken)
One allocator, one rule. Three attested locator sites already pin lowest-free for the same machine idiom — LAC plus the TXL trap — and the prologue composes with it instead of adding a second regime. To overturn: one commit at _indicatorPrologue; the oracle re-checks the site. What overturns it: a compiled listing whose subscripted compare runs with both registers free.
