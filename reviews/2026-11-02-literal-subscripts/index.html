A literal or expression subscript now sets its indicator

Two kinds of subscript compiled with no message and then stopped the run at the base-locator guard. The manuals settle both, so this is decided under the section 12 standing rule. You can overturn it; silence lets it stand.

  1. Decided: a literal subscript is a load-time constant. CELL (2) gets its pointer word under Location Counter 2, beside the base locators. J 02.04.07 calls it “a load-time constant”; J 90.02.01 says counter 2 initializes pointer words with pre-determined constants.
  2. Decided: an index expression moves with its variable. A store into I updates CELL (I + 1) and CELL (2 * I - 1), with the attested five words and different constants. J 02.04.07.01 names A(J, K+1) as updated by SET K=K+2.
  3. Decided, found on the way: a DO FOR now starts at FROM and steps by BY. It set element 1 and stepped one element whatever the loop said. DO RTN FOR I = 3(1)5 summed A(1..3) on master.
  4. Decided: a subscript outside a * VARIABLE ± b refuses, with a named message. CELL (I + J) compiled and stopped at the guard; F p. 31 does not admit it.
  5. Left open, recorded in HANDOVER item 9: two indicators over one array still refuse; a two- or three-subscript indicator with a variable is never set; a name subscript that nothing stores into (F p. 30's MIAMI) is never set.
  6. Cost: 1609 tests pass; test/goldens/90.05-payroll.code is byte-identical, because the sample has no literal or expression subscript and its DO FOR is 1(1)12.

The evidence

Why the “may change” case never applies here: an input record that holds an array transmits (J 90.01.01; the binder, binder.dart:150), only input records locate, and the binder bars a variable-length array. So no array base moves at run time.

Decided

1. The literal subscript: when and how its indicator is set

Master compiled MOVE NUM TO CELL (2) to LAC PI)1,1 / TXL SYS)294,1,0 / STO 0,1, and nothing ever wrote PI)1. The run stopped at the guard.

A. Load-time word under counter 2 (built). The counter-2 run continues from the BL) words into PI), which follows directly, through the last constant indicator: PZE NAME+w,,b for a constant one, PZE 0 for any other before it, as an empty base locator does. Zero object-time cost. A program with no constant indicator, the sample included, keeps every attested word. The one unattested word: USE 2 still prints PI)1. M4-4 left two readings of it, and the ORG after it resets the load address, so it cannot change a run. Reverse: one function in blocks.dart.
B. Store the value at program start. CLA CP)+n / STO PI)n ahead of the first statement. It runs, but it puts object-time words at the program head that J does not describe, against “load-time constant”, and it moves the first statement's address in any program that has one.
C. Recompute before every use. Contradicts J 02.04.07.01: indicators “are evaluated when their subscripts change value”. Adds words at every reference.
D. An ORG PI)n per constant indicator. Same effect as A with a second ORG in counter 2, which no listing shows. A needs none, because PI) follows BL).
E. Refuse with a named message. Breaks your rule of 2026-09-14: F p. 30 and J 02.04.07 show literal subscripts, so the 1962 processor compiled them.
Decided

2. The index expression: which stores update it

Master matched an indicator to a store by comparing the written subscript text with the stored name, so I + 1 never matched I. Element a·V + b is element b plus a·V strides, so the attested shapes take it with new constants only:

  • Recompute (attested at statement 225, LOC 01421–01432): LDQ V / MPY a·stride / XCA / ADD base / STO PI)n, the base now element b. For a plain V, b is 0 and the base is the attested NAME-n, so the sample's RETPREM-2 and INSPREM-2 are unchanged.
  • Constant step SET V = V + c (J 90.02.05's CLA / ADD PI) / STO PI)): adds a·c strides.
  • DO FOR: starts each indicator at element a·FROM + b and steps a·BY strides. For the sample's 1(1)12 that is NAME+0 and one stride, the attested words.

The match is now by the resolved data item, not by text. No alternative fits J 02.04.07.01; refusing breaks the 2026-09-14 rule. Reverse: revert _driven in procedure.dart.

Decided

3. A subscript outside F's form refuses

CELL (I + J), CELL (I * J) or CELL (I / 2) are outside a * VARIABLE ± b. Master compiled them and the run stopped at the guard. No store can set such an indicator with the attested five words, so the generator refuses an index expression outside a * VARIABLE ± b (F p. 31), pinned in test/codegen_refusal_test.dart. Any order of the terms is accepted (1 + I, I * 2), and literal terms fold. Alternative: a front-end diagnostic. No 90.04 message names the form, so it would need a new id of ours; the refusal needs none and is cheap to replace later.

Settled

4. What stays open

  • Two indicators over one array refuse. The generator keys operands by data item in several places (the fetch cells, the subscripted sets), so CELL (I) and CELL (I + 1) in one program need a wider change.
  • A multi-subscript indicator with a variable is never set. A (J, K) stops at the guard on master and on the branch. The recompute shape is attested for one subscript only. All-literal A (2, 1) works.
  • A name subscript nothing stores into is never set, such as F p. 30's MIAMI constant. Verified by a probe.
  • MOVE and ADD CORRESPONDING still update no indicator (already in item 9).

Records: M6-10 in m6-acceptance.md (the M4 record is locked at its word budget, so it points there), and HANDOVER item 9.

Addendum, 2026-11-02: every literal indicator takes its word

Added after the record, in the review of pull request #191. The sections above describe the code at 1378b8c and stand as written. The merge of master at 75aead9 brought pull request #186. It gives each field of a subscripted CORRESPONDING operand its own indicator, numbered after every written one. The written group keeps its own indicator too (M6-9).

What broke. The code at 1378b8c set a constant indicator only when a word read it. Nothing reads the group indicator of MOVE CORRESPONDING G TO TAB (2), so it stayed PZE 0, unlike its fields. M6-10 defines a constant indicator by its subscripts, not by its readers. The record outranks the code, so one option was viable.

Decided at 69be2c5: every indicator whose subscripts are all literals takes its load-time word, read or not. M6-10 now says so. The form check still runs at each indicator's first use.

Rejected: set the group indicator in the two CORRESPONDING paths. It fixes this case only. Any other unread literal indicator would stay empty, and a later reader of M6-10 would find the rule false.

Round 1 of the review, at dc0a60d. Literal terms that fold below one, such as CELL (2 - 3), now draw 182,00, as CELL (0) does (M3-20). The job still compiles. Tests pin the two pointer refusals that the record did not list: a fractional DO FOR bound, and a subscript count unlike the array dimensions.
