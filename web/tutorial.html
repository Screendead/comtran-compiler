Run a payroll
from 1962

The January 1962 manual prints one whole program: a weekly payroll, with the cards it was punched on, the listing the compiler printed, the machine code it made and the report it wrote. The cards are already in the bench at the foot of this page.

Eleven short steps take you from one card to a finished report, and to a mistake the 1962 compiler made that this one keeps.

1. A deck of cards

A program was a stack of punched cards, one line to a card, eighty columns wide. Look at the card at the top of the bench: it is card 1 of the sample, and each dark spot is a hole. A column with holes in it is one character, and the keypunch printed that character along the top edge. Click any position on the card to punch it, and watch the deck text change with it.

2. Three divisions

Scroll the deck. Card 2, *DATA, starts the description of every record the program reads or writes. Card 180, *ENVIRONMENT, ties each file to a tape unit, and card 196, *PROCEDURE, starts the sentences that do the work. The last card, *FINISH, ends the job.

3. Describing a record

Put the cursor on card 11 of the deck, the field RATE. The columns do the talking: the name sits in columns 7 to 22, the level 2 says it sits one step inside the MASTER record, and I in column 36 says it is held in binary. The R beside it keeps it to the right of its space, and the picture 99V999 gives two digits, a decimal point that is never stored, and three more. The language reference sets out every column of a data card.

4. Sentences that pay people

Find COMPUTE.PAY, at card 237. It reads the week’s hours from the detail record and sets the gross pay, at time and a half over forty hours. DO FICA.ROUTINE and DO WITHOLDING.TAX.ROUTINE work out the deductions, and the sentence named NET takes them away. The spelling WITHOLDING is the program’s own.

5. Compile, and read the listing

The bench compiled the deck as soon as the page loaded. Open the 05 Listing tab: this is what the 1962 compiler printed, and the one on this page matches IBM’s print byte for byte. Each statement gets a number, the line and then the clause, so 202,00 is COMPUTE.PAY. The listing ends NO ERRORS WERE DETECTED DURING COMPILATION. Click any line, and its statement lights up in every panel.

6. Run it

Press Run the program. An emulated IBM 7090 loads the machine code from the 06 Code tab and runs it over two input tapes: one of employee records, one of the week’s hours. The first line, AT 199,14 STOP RUN, names the statement that ended the job: clause 14 of statement 199. Below it are the four reports the program wrote: the paycheques, the payroll, one savings bond order and the records that matched nothing.

7. Where the tapes came from

The manual prints the report but not the tapes. We worked them out from the report on PDF page 217 and the record descriptions in the deck, field by field. The derivation of every field on both tapes.

8. Where our run and the page differ

In two places. The page prints the grand total of net pay as 2180.63, but its own department totals add up to 2183.83, and our run prints 2183.83. The page also prints the name WOO once as WCO, where the same field prints WOO twice elsewhere. A test pins both differences, so neither can hide and neither can quietly grow.

9. A mistake the 1962 compiler made

Every line of the payroll report prints RET.PREM, the retirement premium, equal to INS.PREM, the insurance premium, and every net pay takes the insurance premium off twice. The page shows it and so does our run. The cause is in the machine code the manual prints: when a table field starts partway into a 36-bit word, the 1962 compiler could read it from the start of the word, so MOVE RETPREM (POS) fetched INSPREM. We chose to keep that behaviour, so the run matches the page, and a program of your own that reads a table the same way can fetch the wrong field too. The acceptance record, with the machine code that shows the cause.

10. Change one line, run again

Find SET WORKING FICA = .03 * WORKING GROSS in FICA.ROUTINE, at card 260, and change .03 to .04. Press Run the program again. CASPERIAN J’s cheque drops from $80.60 to $79.53, and the department and grand totals move with it. Nobody else’s pay changes, because every other employee on the tapes has already paid, or this week reaches, the 144.00 ceiling the next sentence sets.

11. What this run cannot tell you

The manuals survive in one scanned copy each, read by one reader. Where they leave a question open, the language reference marks the reading we chose as a choice. The manuals never say which messages stopped a compile, so every severity on this site is this project’s own decision. What is built, and what is not, or both manuals, every page beside its scan.

The bench

This is the compiler from the repository, built to WebAssembly and running on this page. Type into the deck, and the panels beside it show what the compiler makes of it. The program already loaded is the payroll sample printed in the 1962 manual: the one program whose source, compiler listing and object code all survive together in the manuals.

Click any line in a panel and its statement lights up in all six: the cards it was punched on, the words it compiled to, and every stage between. The thread is the number the 1962 compiler gave each statement and printed on its own listing.

The card under the cursor

Twelve rows by eighty columns, the rows numbered 12, 11 and 0 at the top, then 1 to 9. The characters along the top are what the keypunch printed above the holes it cut; the holes are the part the compiler reads. Click a position to punch it, and the deck text follows. Cut a combination no character matches and the card leaves the character form for the punch form, which is what the deck format is for.
