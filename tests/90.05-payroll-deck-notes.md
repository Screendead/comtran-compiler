# tests/90.05-payroll.deck — provenance and reconstruction notes

*Created 2026-08-02. Re-keyed card deck of the J28-6169 Appendix 90.05 sample
payroll program — the only surviving COMTRAN program with known-correct output
(the printed report, J28-6169 PDF p. 217).*

## What this file is

A reconstruction of the **source card deck** of the 90.05 sample problem.
Since 2026-08-03 the authoritative form is the punch-level canon file
`90.05-payroll.ctdeck`, generated once from the re-keyed text and verified by
round trip; `90.05-payroll.deck` is now its generated text mirror (decision
D0.5; format in `docs/design/deck-format.md`). The mirror renders one line
per card, card columns 1–72 significant, columns 73–80 (identification)
blank throughout and trimmed along with all trailing blanks. 293 cards:

| Cards | Content |
|---|---|
| 1 | `*COMPILE` control card |
| 2–179 | `*DATA` header + 177 data description cards (statements 1,00–172,00; five entries occupy two cards each — see *Continuation cards* below) |
| 180–195 | `*ENVIRONMENT` header + 15 environment cards (statements 173,00–186,00; the PAYFILE FILE specification occupies two cards) |
| 196–293 | `*PROCEDURE` header + 97 procedure cards (statements 187,00–229,00) |

## Sources and method

- **Character content** is taken from the verified transcription
  `comtran-manuals/J28-6169/90.05-sample-program.md` (compilation listing,
  PDF pp. 192–197), which reproduces card body columns 7–72 per J 02.02.01.
- **Column layout** was *measured from the page scans*
  (`comtran-manuals/J28-6169/images/page-192.png` … `page-197.png`) by
  pixel-level analysis: per-page calibration of printer pitch (~9.1 px/char at
  the scans' resolution) against structurally fixed columns (Level 23–24, Type
  25–30, Quantity 31–35, Mode 36, Justify 37, Description 38–71, per F p. 65 /
  J 02.06.01), then per-line mapping of every ink group to card columns.
  The transcription's own spacing is normalized and was **not** relied on for
  layout.
- Content was verified after assembly by a whitespace-insensitive
  character-stream comparison of the whole deck against the transcription
  (identical except the one erratum noted below).

## What is deliberately NOT in the deck

Everything in the listing that is compiler output rather than card content:
page headers, the `CTC`/`CTD`/`CTE` compiler-phase markers (printed on-line at
phase entry, J 05.03), the `NO ERRORS...` message, the statement-number and
LOC columns, and the compiler-generated `GN)nnn` names ("names generated by
the Compiler ... shown in the name field of Procedure statements or Data
entries unnamed by the programmer", J 02.02.01) — those entries' name fields
are blank on the cards, as punched.

## Layout facts established from the scans

- **Serial columns 1–6 are blank** on every card: the listing's serial column
  is empty throughout.
- All three division headers have their asterisk in **column 7**. An earlier
  reading put `*PROCEDURE`'s asterisk in column 8; cell-boundary re-measurement
  (2026-08-03, adversarial verification of M1) shows its `*` in the same
  character cell as the `G` of `GN)000` on the next line — and `GN)nnn` prints
  in the name field, card column 7 (J 02.02.01). `*ENVIRONMENT` aligns with
  `INPUTMASTER` and `*DATA` with `MASTER` the same way, and F is explicit
  ("the asterisk is in Column 7", F p. 65). The deck was corrected to column 7
  on 2026-08-03.
- The `*COMPILE` card (an earlier-format counterpart of the J 02.01 `$CMPLE`
  card) reads `*COMPILE` from column 7, option `LIST` at column 16, and
  secondary identifier `CT PUBLICATIONS` at column 55 — the option and
  secondary-identifier positions matching the documented `$CMPLE` fields
  (J 02.01.01–02.01.02). Anchored on the console `CTC` print at print
  position 1; the identifier's start carries ±1 column uncertainty.
- Data names are indented freely within the Name field (7–22); indent is
  hierarchical but not uniform (e.g. MASTER's subfields step 9/11/13 by level,
  DETAIL/CHECK/PAYRECORD subfields step 8/9, TABLE.ITEM's subfields are flush
  at 7). Several names end flush at column 22 with the level abutting at
  23–24 (`EMPLOYEE.NUMBER02`, `CNTRLCHARSECLIN02`, `ENDFRSTLINE` + `02RCDMRK`).
- Levels are punched as in the listing: single digits right-justified in
  column 24, two-digit forms `01`/`02`/`03` in 23–24 (both styles appear;
  J 02.05.01 allows either).
- TABLE's constant-only continuation cards (statements 145–167, odd ones)
  carry their quoted constant starting in **column 38** (Description field),
  not aligned under the preceding pictorial's constant.
- `TABLE.ITEM`'s repetition count `12` sits right-justified in Quantity
  columns 34–35.
- Procedure statements: procedure-names start at the name margin (column 7);
  sentence text and continuation lines start at column 13 except statement
  187's operand continuation lines (column 18) and lines whose first word
  follows a long name. Statement 208's first line runs exactly through
  column 72.

## Reconstruction decisions (unrecoverable from the listing)

1. **Column-72 continuation character = `X`** on the six two-card entries
   (statements 3, 21, 22, 103, 107 — name continued; statement 181 — FILE
   options continued). A non-blank column 72 is required for continuation
   (F p. 84; J 02.06.01.01), but the processor "replaces the contents of
   column 72 with a blank in Data and Environment lines" (J 02.03.01 §2.c),
   so the listing cannot show which character was punched. Any non-blank
   character is equivalent to the language.
2. **Far-right spacing of long free-form procedure lines** carries ±1-space
   uncertainty: the scans show a mild progressive horizontal stretch (~1.5%
   per column), corrected during measurement, but word gaps beyond ~column 60
   rest on local inter-word measurements. All gaps were resolved to the
   best-fit integer; none is semantically significant.
3. Interior spacing of the two report-header literals (statements 80, 82) is
   now *measured*, not just length-derived: `DEPARTMENT` starts at column 55
   ⇒ ten spaces after the opening quote; `TOTALS` starts at column 46 ⇒ one
   leading and five trailing spaces. Closing quotes (columns 66 and 57) are
   forced by the A(21)/A(12) field lengths.

## Transcription errata found during re-keying (conversions untouched)

The manual conversions are read-only; these are candidates for Jack to
authorize as errata against `90.05-sample-program.md`:

1. **Statement 43,00: the punched name is `CNTRLCHARSECLIN` (15 characters),
   not `CNTRLCHARSECLINE`.** The scan (p. 192) shows `CNTRLCHARSECLIN02` with
   the level `02` abutting directly after the final `N` in columns 23–24; a
   16-character name would end in column 23 and could not abut a 23–24 level
   field. Confirmed at high zoom and by pixel measurement (17 contiguous
   character cells from column 8). The deck uses `CNTRLCHARSECLIN`.
2. **Statement 203, line 2 reads `1.5 -20)`** (no space between the minus and
   `20`), where the transcription prints `1.5 - 20)`. Confirmed by grid
   overlay at p. 196.
3. Minor spacing normalizations in the transcription relative to the printed
   listing (the deck follows the scans): double spaces printed in
   `SPECIFPAYFILE,  UNIT1` and `OPENW, CLOSER` (statement 182); `MOVE  BLANKS`
   (statement 199); `FILES,  STOP RUN.` (statement 199); `HIGH.VALUE,  GO`
   (statement 198); `BONDENOMINATION,  GO TO BOND.END.` (statement 220);
   single space in `CALL (MASTER` (statement 187) where the transcription
   shows two; and similar one-space differences in name-margin gaps.
